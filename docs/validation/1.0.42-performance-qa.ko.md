# 알맹Re 1.0.42 성능·품질 검증

빌드 97 · 검증일 2026-10-20 · 한계를 명시한 사전 릴리스

**공개 판단 범위: 확인한 동작과 자원 관측, 남은 한계를 함께 공개합니다.** 실제 대량 탐색과 30분 이상 혼합 사용의 계측 기록은 완결됐습니다. 알려진 네이티브 영상 처리 한계를 성공한 렌더링으로 바꾸지 않았으며, 전체 파일 렌더링 성공이나 무조건적인 성능 합격을 뜻하지 않습니다.

처리량 검사와 실제 앱 관측은 서로 다른 조건입니다. 썸네일 파이프라인 검사는 최대 두 요청을 유지하고 정상 활성 상태의 고정 자원 정책을 사용했습니다. 실제 설치 앱의 혼합 사용에서는 시스템 부하를 반영하는 기존 자원 정책을 사용했습니다. 어느 검사에서도 OS 파일 캐시와 Quick Look 캐시를 비우거나 통제하지 않았습니다.

## 확인한 변경

깊은 필터 위치에서 큰 썸네일로 전환했을 때 실제 보이는 카드가 정밀 보완 대상에서 빠지던 경로를 수정했습니다. 표시 대상은 네이티브 카드와 실제 뷰포트의 교차로 확인하며, 기존 비트맵을 유지합니다. 파일 버전과 표시 조건이 같은 결과는 재사용하고, 취소되거나 교체된 요청의 늦은 결과가 현재 타일을 덮지 않도록 합니다.

캐시는 확인된 삭제와 실제 남은 파일을 기준으로 집계하고, 집계할 수 없는 상태는 확인 불가로 구분합니다. 설정에서 사용량 확인과 캐시 비우기·재생성을 확인했습니다. 디스크 미리보기 128MiB와 정밀 캐시 384MiB를 구분하며, 캐시 한도를 늘려 결과를 보완하지 않았습니다. 이 예산은 코덱 임시 공간과 화면 이미지를 포함한 앱 전체 메모리 상한이 아닙니다.

4장 이하 다중보기는 품질을 우선하고, 5장 이상은 빠른 미리보기와 탐색 반응을 우선합니다. 탐색이 멈추면 필요한 표시 크기로 보완합니다. 지도·비교·몽땅보기·EXIF 검색·분류와 RAW·HDR 및 원본 출력 경로를 유지했습니다.

## 전체 회귀와 표본 품질

같은 동결 소스로 다시 수행한 전체 회귀는 **1,261개 통과, 36개 생략, 실패 0개**였습니다. Swift Testing 1,256개와 네이티브 XCTest 5개가 통과했습니다. 생략한 검사는 실행한 검사에 포함하지 않았고, 매개변수 인수별 실행을 선언 수에 중복 합산하지 않았습니다.

첫 회귀의 실패 13개와 이전 전면 조건을 충족하지 못한 실행은 별도 보존했습니다. 새 재실행의 통과로 이전 기록을 고치거나, 각 실패가 모두 잠금 때문에 발생했다고 단정하지 않았습니다. 여기서 실패한 검사 13개와 아래의 네이티브 영상 13개는 서로 다른 집계입니다.

별도 품질 검사 4개도 통과했습니다. 화면 크기·HDR·회전·크롭 12개 조합의 표본 픽셀, 일부 RAW의 768픽셀 결과 전체 픽셀·색 프로파일·알파·크기, 내장 미리보기와 보완 경로를 대조했습니다. 원본 출력은 표시용 재사용 경로를 우회하는 것을 확인했습니다. 모든 원본 해상도 픽셀, 모든 내보내기 형식과 실제 HDR 패널 밝기를 전수 검증한 결과는 아닙니다.

## 전체 썸네일 파이프라인

비어 있지 않은 805개를 실제 썸네일 경로에 요청했습니다. **DNG 716개, HEIC 1개, 영상 75개에서 유효한 최대 256픽셀 썸네일을 반환해 총 792개가 성공했습니다.** 나머지 영상 13개는 해당 Mac의 네이티브 처리 한계로 별도 분류했습니다.

| 구간 | 관측값 | 해석 범위 |
|---|---|---|
| 앱 캐시가 빈 첫 805개 요청 | 33.6947초, 검사 프로세스 누적 CPU 27.211초 | 792개 성공과 13개 실패를 모두 포함 |
| 성공한 792개만 RAM 캐시를 비운 뒤 역순 재사용 | 2.4443초, 누적 CPU 1.2974초 | 디스크 적중 792개, 누락 0개. 원본 버전 stat 확인은 포함하고 원본 픽셀 디코딩을 허용하지 않은 캐시 전용 경로 |
| 생성된 완료 미리보기 | 792개, 73,051,239바이트 | PNG 파일의 논리 크기. 파일시스템 할당량·임시 버퍼와 별도 |

첫 요청과 역순 재사용은 대상 수와 수행한 일이 다릅니다. 두 값을 속도 개선 배수로 비교하지 않습니다. 이 시간은 요청·대기·디코딩·캐시 저장 또는 복귀를 포함한 파이프라인 반환 시간이며, 실제 스크롤 후 화면에 빛이 출력되는 시간이나 영상 재생 시간은 아닙니다.

## 실제 설치 앱의 조작

준비된 사진 목록 729개를 사용하는 별도 네이티브 실행에서 필터 적용·변경·해제 7단계, 왕복 탐색, 크기 변경 4단계, 2·4·6·9장 보기를 확인했습니다. 크기 변경에서는 비어 있지 않은 가시 대상 71/71, 30/30, 4/4, 20/20이 필요한 비트맵 크기를 충족했습니다. 큰 단계는 1,536픽셀 크기 구간을 확인했습니다.

크기 변경 입력은 실제 슬라이더 클릭입니다. 이를 연속 드래그 성공으로 표현하지 않습니다. 다중뷰어의 해당 검사에서는 정밀 결과와 네이티브 비트맵 연결을 확인했지만, 뒤의 장시간 관측에서 모든 타일의 정밀 품질을 같은 방식으로 재검사한 것은 아닙니다. 같은 결과를 내는 서로 다른 검색의 실제 시작·완료와 원래 검색 복원, 순서·페이지·선택·기존 이미지 보존도 확인했습니다.

별도 수동 검사에서는 GPS 항목 704개 중 지도 영역의 13개 사진을 표시한 뒤 해제해 817개 목록으로 돌아왔습니다. 깊은 위치에서 실제 포인터 드래그로 8개를 선택하고 휠 왕복 뒤 선택 유지를 확인했습니다. 설정의 캐시 비우기 후 RAM·디스크 집계 0과 탐색 재개 후 재생성을 확인했습니다. 이를 실제 모든 정밀 디코딩 시점과 동기화한 삭제 경쟁 검사로 확대하지 않습니다.

**크기 전환에서는 최대 약 2.36초의 추가 타이머 공백을 관측했습니다. 원인은 아직 확정하지 못했습니다.** 이것을 측정 도구만의 비용으로 결론 내리지 않았고, 지연 문제가 모두 해결됐다고 표시하지 않았습니다. 별도 스택 관측을 이 공백의 원인으로 연결할 근거도 충분하지 않습니다. 이 관측이 있으므로 낮은 평균이나 짧은 대부분의 표본만으로 모든 조작이 매끄럽다고 판정하지 않습니다.

## 30분 이상 혼합 사용

최종 장시간 관측은 **1,864.30초, 조작 343회**였습니다. 사진 4·6장 보기, 전체 사진·영상 목록, 영상 포스터 4·6장, 파일명·EXIF 필터 변경과 해제, 지도 선택과 다른 보기로의 전환을 반복했습니다. 지도에서는 위치가 있는 항목 704개와 프로그램에 의한 네이티브 핀 선택·영역 검색을 관측했습니다. 지도 타일의 네트워크 로딩이나 물리 화면 출력 시간은 측정하지 않았습니다.

| 항목 | 결과 |
|---|---|
| 기록된 조작 실패 | 0회 |
| 캐시 예산 초과 | 0회 |
| 자원 표본 | 1,653개 모두 앱 전면·창 가시성 조건 충족 |
| 표본 간격 | 최대 2.108초, 3초 초과 0회 |
| 평균 CPU | 한 코어 기준 71.81% |
| 누적 CPU | 1,338.786초 |
| 최대 표본 footprint | 약 2.42GB |
| 정지 관측 | 같은 기준 사진과 창 크기로 30초씩 8회 |

CPU 100%는 한 코어를 뜻합니다. 평균은 탐색과 정지, 진단 부하를 포함한 앱 프로세스 전체 관측입니다. footprint에는 앱이 보유한 이미지·코덱·시스템 프레임워크 등의 비용이 포함되며 캐시 사용량과 같지 않습니다. 표본 사이의 순간 최대치나 물리적인 전면 상태 연속성을 증명하지 않습니다.

정지 구간에서는 같은 사진의 정밀 비트맵과 창 크기, 처리 중·대기 중 작업 0개를 확인했습니다. 각 구간은 30초 이상이며, 경계를 걸치는 표본을 제외한 안정 구간이 약 28.26~29.22초를 덮었습니다. 정지 중 footprint 중앙값은 최초 약 212.8MB였고, 혼합 작업을 거친 뒤 약 510.7~583.2MB 범위, 마지막 약 582.3MB였습니다. 초기 상태와 이후 캐시·지도 프레임워크 상태가 같다고 볼 수 없으므로 누수 유무나 메모리 절감의 증거로 삼지 않습니다. 메모리 압박 알림이나 저전력 모드는 이 실행에서 관측되지 않았습니다.

## 알려진 입력 한계와 판정

빈 DNG 12개는 정상 썸네일 성공 대상에서 제외했습니다. 특정 VP9 영상 13개는 해당 파일 버전과 Mac에서 네이티브 포스터 추출 실패 및 재생 불가를 별도로 확인했습니다. 모든 VP9 파일이나 모든 macOS 기기의 지원 범위로 일반화하지 않습니다.

장시간 실행의 **영상 종료 오류 관측 57회는 그 13개 중 실제 방문한 11개 버전과 정확히 연결됐습니다.** 파일 경로의 비공개 식별값, 크기, 수정 시각과 현재 요청 버전을 대조했으며 허용 오차를 두지 않았습니다. 원시 오류 종류를 다른 오류로 바꾸거나, 이 57회를 성공한 렌더링으로 계산하지 않았습니다. 나머지 알려진 2개 버전도 이 장시간 실행에서 모두 방문했다고 주장하지 않습니다.

최종 슬롯은 현재 원본 버전에 맞는 수락 결과 또는 정확히 확인된 형식 한계로 분리됐습니다. 미확인 최종 슬롯, 겹치거나 빠진 슬롯 분할은 없었습니다. 이 검사는 88개 영상의 모든 구간 재생·소리나 장시간 실행의 모든 타일에서 정밀 비트맵과 물리 출력을 확인한 검사가 아닙니다.

판정기는 **한계를 구분한 계측 기록 완결을 참으로**, **엄격 전체 성공과 전체 렌더링 수용을 거짓으로** 유지했습니다(`strictAccepted=false`, `fullRenderingAccepted=false`). 기록이 빠짐없이 분류됐다는 의미와 모든 파일이 성공적으로 그려졌다는 의미를 구분한 결과입니다. 여기서 공개하는 것은 이 범위의 검증과 한계이며, 무조건적인 전 포맷·전 기종 성능 합격은 아닙니다.

## 이전 실행과 제외

같은 빌드의 앞선 장시간 실행은 약 949.09초·889.69초·23.16초에 중단됐고 전면 조건을 충족하지 못했습니다. 네 번째 실행은 1,868.18초를 관찰했지만 전면 또는 가시성 조건이 깨진 자원 표본 108개가 있어 엄격 수용을 거부했습니다. 그중 가시성 실패 69개는 같은 표본에 겹치므로 별도 69개로 더하지 않습니다. 이탈 원인을 사용자나 자동화 또는 특정 보안 요청으로 단정하지 않으며, 깨진 구간을 성능 비교에 쓰거나 실행들을 이어 붙여 30분 성공으로 계산하지 않았습니다. 앞선 실제 크기 변경 실행의 전면 이탈 실패도 완료된 재실행과 구분해 보존했습니다.

## 보존·현지화와 남은 범위

원본을 변경·삭제하지 않는 절차로 검사했습니다. 전체 880개 항목은 일반 파일 879개와 디렉터리 1개입니다. 검사 전후 파일 집합·크기·나노초 단위 수정 시각 등의 메타데이터와 정상 사용자 설정의 일치를 확인했습니다. 원본 내용 전체의 체크섬은 계산하지 않았습니다. 최신 빌드와 설치 실행 파일의 일치, 진단 종료 뒤 원래 사진 작업·확대·HDR 설정을 보존한 일반 실행 복원도 별도로 확인했습니다.

현지화 화면 근거는 빌드 96에서 수행한 10개 언어의 렌더 검사를 재사용했습니다. 320개 결과 중 140개를 실제로 검수했고 나머지 180개는 목록·해시 대조 범위입니다. 빌드 97의 해당 UI 구성과 번역이 동일함을 확인한 계보 재사용이며, 빌드 97의 모든 화면을 새로 렌더해 검수했다는 뜻은 아닙니다. 기존 상세 설명서·화면 캡처·PDF는 이번 검증에서 갱신하지 않았습니다.

이전 빌드와 측정 정의·대상이 같은 전체 앱 성능 쌍은 확보하지 않았으므로 속도·CPU·메모리 개선률을 제시하지 않습니다. GPU·에너지, 물리적 화면 합성 시간과 FPS, 실제 HDR 패널 밝기, Intel 실기 성능, 모든 원본·내보내기 전수 품질도 남은 범위입니다. 배포본은 ad-hoc 무결성 서명이며 Apple Developer ID 서명·공증은 적용되지 않았습니다.
