## 2026-09-04 — 0.2 패널·입력·정보·로딩 개선

### 요청 반영

- 썸네일 패널을 위·아래·왼쪽·오른쪽 또는 숨김으로 배치하고 선택을 저장
- 확대 이미지 팬을 왼쪽 드래그, Space+왼쪽 드래그, 오른쪽/가운데 버튼, 트랙패드 두 손가락 방식으로 설정 가능하게 확장
- 툴바를 i 정보와 e 편집 버튼으로 분리
- 파일/픽셀/색상/TIFF/EXIF/GPS 정보를 표시하고 Apple 지도·Google 지도 표준 URL 연동

### 성능과 안정성

- 목록 썸네일을 macOS Quick Look 캐시로 분리해 정밀 렌더 actor의 대기열과 경쟁하지 않게 변경
- 대용량 이미지는 Quick Look 미리보기를 먼저 띄운 뒤 Image I/O/Core Image 결과로 교체
- 일반 SDR은 목표 화면 크기로 선축소하고 HDR·gain-map만 고정밀 경로를 유지
- 현재 화면을 배경 선읽기 대상에서 제외하고, 빠른 탐색 시 이전 선읽기를 취소
- 작은 원본은 썸네일 상한을 원본 치수로 제한해 업스케일과 Image I/O 경고 방지
- 정밀 캐시 상한을 물리 메모리의 1/24(128~512MB)로 낮춰 장시간 탐색 안정성 개선
- 내보내기용 원본 해상도 프레임은 캐시에 남기지 않아 대용량 RAW 저장 후 메모리 회수
- Quick Look 등 시스템 동적 프레임워크를 활용해 별도 대형 코덱 의존성은 추가하지 않음

### 확인

- 패널 배치, 팬 입력 매핑, 지도 URL, 실제 EXIF/GPS JPEG 읽기 테스트 추가
- Swift 6.2 debug 빌드와 자동 테스트 10개 통과
- Apple Silicon/Intel Universal 2 앱 3.56MiB, 배포 ZIP 881KiB
- 릴리스 디버그 심볼 제거, ad-hoc 서명·plist·ZIP 무결성 검증 통과

## 2026-09-03 — 0.1 기반 구현

### 결정

- 반디뷰의 어두운 이미지 캔버스와 하단 플로팅 조작부를 참고하되 macOS 통합 툴바, 사이드바, 설정 창으로 재구성했다.
- 성능 엔진은 Rust부터 도입하지 않고 Image I/O + Core Image로 시작했다. 현재 macOS가 AVIF, JPEG XL, HEIC, WebP, EXR, DDS와 주요 RAW를 네이티브로 제공하기 때문이다.
- 시스템 미지원 범위를 검증하기 위해 QOI와 PCX 디코더를 앱 내부에 분리했다.
- 원본 파일을 수정하지 않는 것을 기본 안전 규칙으로 정했다.

### 구현

- 빈 Swift Package 기반 macOS 앱 생성
- 폴더/파일/드롭 열기, 자연 정렬, 지연 로딩 썸네일
- 전체 보기 및 1~10장 자동 그리드
- 핀치 확대, 드래그 팬, 스와이프 및 키보드 탐색
- 사용자 지정 단축키 설정
- 애니메이션 이미지 재생
- GPU Core Image 보정과 다중 포맷 내보내기
- HDR/SDR 출력 전환과 제한형 메모리 캐시
- 앱 번들 빌드 스크립트와 GitHub용 기본 문서
- Apple Silicon/Intel Universal 2 앱 패키징

### 확인

- Swift 6.2 / Xcode 26.3 환경에서 debug/release 빌드 성공
- 레이아웃, 회전, QOI, PCX, PNG 내보내기 자동 테스트 6개 통과
- 실제 macOS 창에서 폴더 스캔, 썸네일, 단일/5장 이미지 렌더링 확인

### 다음 우선순위

1. 실제 대용량 RAW·EXR·파노라마 자료로 타일 렌더러 벤치마크
2. 여러 파일 일괄 변환 및 진행률/취소
3. ZIP/7z/RAR 이미지 묶음 읽기
4. EXIF 상세 보기, 북마크, 슬라이드 쇼
5. VoiceOver와 키보드 포커스 접근성 점검
