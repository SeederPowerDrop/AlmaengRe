# AlmaengRe 性能测试记录

[한국어](ko.md) · [English](README.md) · **简体中文** · [Русский](ru.md) · [Français](fr.md)

本文记录 AlmaengRe 1.2（构建 110）采用的性能改进，以及之后的侧栏实验。11 月的测试使用 Apple M3、24 GiB 统一内存和 macOS 15.7.5。M2 配备 16 GiB 内存的机型仍待实机验证。

| 测试 | 实测结果与结论 |
| --- | --- |
| 构建 97，大型媒体库基准 | 1,261 项回归测试通过，36 项跳过。805 个非空文件中有 792 个成功生成缩略图。其余 13 个为测试机原生视频处理受限的案例。混合使用测试持续 1,864.30 秒，执行了 343 次操作。[构建 97 完整报告（韩文）](../validation/1.0.42-performance-qa.ko.md) |
| 构建 105–106，打开与滚动 | 使用 729 个项目和 717 张预先生成的缩略图，完成四次前台测试。设定大小后，为 25 个可见项目生成精细缩略图并清空队列，105 用时 1.482–1.759 秒，106 用时 1.426–1.686 秒。两组区间重叠。失去前台焦点或触发内存保护的轮次没有纳入速度对比。 |
| 构建 106–107，返回 RAW 页面 | 六图视图返回页面后，106 的对照复测需要 1,056–1,189 毫秒才发布全部精细帧，107 为 92–215 毫秒。首次生成 12 张图像后，后续精细渲染次数为零。该组对比中，初次显示和往返的 CPU 时间由 18.09 秒降至 9.03 秒，应用物理内存峰值采样由 1,401 MiB 降至 1,219 MiB。调整的是五图及以上视图中原有 128 MiB 缓存预算的分配。 |
| 构建 107–108，调整缩略图大小 | 在相同的 729 项视图和拖动操作下，主循环最大额外间隔由 1,481–1,552 毫秒降至 816–895 毫秒。拖动时滑块持续更新，网格延后调整。这几轮测试中，从手势开始到界面稳定的总时间略有增加。 |
| 构建 108–109，应用与清除 EXIF 筛选 | 同等前台条件下，四个 EXIF 更新阶段的最大间隔由 628 毫秒降至 598 毫秒。首次搜索全程仍约为 4.4 秒。验证了结果、顺序及选中项恢复。 |
| 构建 109–110，再次优化大小调整 | 简化底部工具栏布局后，每轮主循环的最大额外间隔由 670–944 毫秒降至 441–449 毫秒。在同样的 226.4→78.206 pt 拖动结束后，25 张可见缩略图均通过 256 px 检查。 |
| 构建 110，RAW 与视频混合 | 同屏显示 5 张 RAW 和 1 个视频时，独立队列观测到的视频输出约为 60 fps。直接滚动侧栏时，主线程最大观测间隔为 433–512 毫秒，同时滚动、选择 RAW 与缩放时为 573–606 毫秒。 |
| 构建 111，侧栏实验 | 复用行的原型将直接滚动的间隔降至 48.5–49.2 毫秒，但在 729 项的筛选测试中触发了 12 次 AppKit 表格重入警告。固定行尺寸与单列网格在混合操作中没有取得一致改善，只布局可见行的原型使混合操作的间隔增至 825–898 毫秒。1.2 采用构建 110。 |

## 如何解读结果

每组直接对比都使用相同的文件列表、预生成缩略图、视口和输入顺序。条件允许时交换运行顺序，并隔离测试设置与缓存。资源保护测试监控了系统内存压力、应用物理内存采样及交换空间。完成的构建 110 混合测试中，内存压力正常，交换空间用量增量为零。缓存预算用于缓存数据，应用内存还包括解码后的图像、编解码器和渲染工作区。

帧发布、计时器间隔和独立视频输出是不同的指标。屏幕实际显示延迟与合成器丢帧需要单独测量。仍待验证的项目包括 16 GiB M2 上的长时间混合使用、其他应用的响应，以及在网格较深位置调整缩略图时保持选中照片可见。
