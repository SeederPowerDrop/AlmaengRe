## 왜 핵심 엔진이 Rust가 아닌가

이 앱의 주 경로는 이미 Apple이 C/C++·GPU 수준에서 최적화한 Image I/O, Core Image와 Metal입니다. 같은 파일을 Rust로 다시 디코딩한 뒤 SwiftUI로 복사하면 메모리 복사와 컬러 프로파일 변환이 하나 더 생기고, 최신 macOS RAW/HDR 지원을 중복 구현해야 합니다.

따라서 UI 상태는 Swift, 디코딩/색상/필터는 Apple 프레임워크, 시스템에 없는 작은 오픈 포맷만 독립 코덱으로 둡니다. 이후 libjxl/libheif/LibRaw 같은 외부 엔진이 실제 측정에서 필요해지면 ImagePipeline 뒤에 어댑터로 추가할 수 있습니다.

## 성능 설계

- 폴더 스캔과 이미지 파이프라인은 actor로 UI 스레드에서 분리합니다.
- 그리드 셀은 화면에 보일 때만 작업을 요청하며 사라지면 취소하고 이미지 참조를 해제합니다. 세대 번호로 늦게 끝난 요청이 새 셀을 덮는 것을 막습니다.
- 목록은 Finder와 같은 Quick Look 썸네일 캐시를 사용합니다. 큰 이미지도 빠른 미리보기를 먼저 표시하고 정밀 렌더가 완료되면 교체합니다.
- 화면 크기가 정해진 SDR 이미지는 Image I/O에서 먼저 축소합니다. 보정이 없으면 ICC 프로파일을 가진 비트맵을 바로 표시하며, 보정·HDR/gain-map에는 Core Image 경로를 유지합니다. GPU·CPU 컨텍스트는 실제 필요한 순간 작업 actor에서 생성합니다.
- ImageResourceGovernor는 정밀·Quick Look·이미지 정보 읽기의 동시 실행 예산을 공유합니다. 이전의 정밀 최대 4개와 Quick Look 최대 3개를 독립적으로 실행하지 않습니다. 16 GiB 이상·8코어 Apple Silicon, 내부 SSD·정상 상태의 기본 쾌적 모드는 합쳐 최대 2개입니다. ImageWorkScheduler는 같은 파일 버전·크기·처리 조건 요청을 병합하고 표시 요청을 선읽기보다 먼저 처리합니다.
- 설정의 최우선·쾌적·일반·느림 상한은 각각 공유 최대 4·2·1·1개이며 코어·메모리가 적으면 더 줄어듭니다. 정상 표시 작업은 각각 userInitiated·utility·utility·background, 선읽기는 항상 background입니다. 일반은 작업 사이 최소 25ms, 느림은 100ms를 둡니다. 이미 실행 중인 동기 코덱의 우선순위를 강제로 바꾸거나 성능·효율 코어를 고정하지 않습니다. [Apple QoS](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/EnergyGuide-iOS/PrioritizeWorkWithQoS.html)
- RAW·TIFF·실제 HDR 등 원본 작업 공간이 큰 경로와 원본 해상도 내보내기는 별도 actor에서 한 장씩 처리하되 공유 예산에 포함합니다. Quick Look은 앱이 제출하는 동시 요청을 제한하며 OS 서비스 내부의 다른 앱 요청까지 통제하지 않습니다.
- 마지막 요청자 취소 시 네이티브 Quick Look 취소까지 전달합니다. 동기 디코더는 실제 종료할 때까지 실행 슬롯을 유지하므로 빠른 탐색으로 동시 디코딩이 늘지 않습니다.
- 다음 페이지 우선 Quick Look 미리보기만 선읽기합니다. 내부 SSD 정상 상태에서 최우선은 최대 4장/150ms 후, 쾌적은 2장/350ms 후, 일반은 1장/650ms 후, 느림은 선읽기 없음입니다. 이웃 사진은 한 장씩 요청하고 현재 정책을 다시 확인합니다. 타일과 동일한 크기를 사용하고 몽땅보기에서는 별도 선읽기를 중단합니다.
- ImageStorageClassifier는 선택한 볼륨의 공개 속성과 연결된 전체 디스크·부모 장치 속성만 확인하며 분류 결과를 최대 32개 볼륨·30초간 캐시합니다. 확인된 외장 SSD는 공유 최대 2개·선읽기 1장/최소 600ms 후, SD·네트워크·분류 불명은 1개·선읽기 없음·작업 사이 최소 40ms입니다. SD의 이동식·Secure Digital 속성은 solid-state 속성과 상위 USB 연결보다 우선합니다. 알 수 없는 외장 장치의 속도를 추측하거나 사진 파일로 속도를 시험하지 않습니다. [Apple 볼륨 속성](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumeisinternal), [Apple Disk Arbitration](https://developer.apple.com/library/archive/documentation/DriversKernelHardware/Conceptual/DiskArbitrationProgGuide/ManipulatingDisks/ManipulatingDisks.html)
- 정밀 요청은 256픽셀, 썸네일은 128픽셀 버킷으로 묶습니다. 창 크기 변경은 60ms 동안 기존 이미지를 유지한 뒤 새 크기를 읽습니다.
- 몽땅보기는 44.8~665.6pt 사이로 셀 크기를 연속 조절하며 선택값을 저장합니다. 좁은 창에서는 실제 셀 크기만 가용 너비에 맞추고, adaptive 열의 최대 1.35배 너비·Retina 배율·10% 여유를 반영한 썸네일을 요청합니다. 고품질 보간은 뷰어 고화질 확대 설정과 독립적으로 항상 적용합니다. 512px 이상 요청은 빠른 미리보기 뒤 90ms 디바운스를 거쳐 원본 기반 결과로 보강하며, 크기만 바뀐 경우 기존 이미지를 유지합니다. URL·파일 버전·보정·HDR 조건이 다른 결과는 재사용하지 않고 세대 검증도 유지합니다.
- 정밀·썸네일은 bytesPerRow × height를 추적하는 바이트 LRU 캐시를 사용합니다. 16 GiB Mac의 기본 쾌적 캐시는 각각 128·64 MiB이고, 최우선 256·128 MiB, 일반 96·48 MiB, 느림 64·32 MiB입니다. 더 작은 메모리는 모드별 물리 메모리 비율로 상한을 더 줄입니다. 파일 크기·수정 시각도 키에 포함하며 예산 감소·캐시 비우기 이전 세대의 완료 결과가 캐시를 다시 채우지 못하게 합니다.
- 화면 맞춤 페이지의 출력 비트맵은 HDR 정사각형 기준 총 128~256MiB 예산으로 크기를 제한합니다. 명시적 확대·실제 크기 보기는 기존 8K 해상도 상한을 유지하며 이 페이지 예산의 예외입니다. 디코더 임시 메모리·GPU·화면 참조는 별도입니다.
- ImageSystemResourceMonitor는 utility 큐의 2초 타이머로 우리 앱을 포함한 전체 CPU 부하를 읽습니다. 65% 이상은 선읽기 중지·최대 2개, 80% 이상 연속 2회는 최대 1개로 낮춥니다. 심한 CPU 제한은 60% 이하가 연속 3회 확인된 뒤 해제합니다. 첫 표본은 기준값만 만들고 프로세스 목록이나 다른 앱의 이름은 수집하지 않습니다.
- 메모리 압박·발열·저전력·앱 활성 상태는 시스템 이벤트로 받습니다. 비활성·저전력·심한 발열·메모리 압박은 공유 최대 1개·선읽기 중지·작업 사이 최소 60ms를 적용합니다. 비활성은 background와 캐시 1/4, 메모리 경고도 캐시 1/4, 심각한 메모리 압박은 캐시 0으로 줄입니다. 가벼운 발열은 최대 2개·선읽기 1장, 심각한 발열은 background·작업 사이 최소 150ms입니다. 최우선에서도 보호를 유지하고 회복 시 현재 모드·저장장치 상한으로 돌아갑니다. 모니터 종료 시 타이머와 알림 관찰을 해제합니다. [Apple 메모리 압박 감지](https://developer.apple.com/documentation/dispatch/dispatchsourcememorypressure)
- HDR 경로는 Core Image RGBAh, extended-linear Display P3와 EDR이 활성화된 전용 CALayer를 사용합니다.
- 집중 뷰어의 기본 확대는 CALayer에 선형 확대·삼선형 축소 필터를 적용해 핀치 중에도 픽셀 경계를 부드럽게 보간합니다. 제스처가 끝나면 확대 배율에 맞는 더 큰 디코딩 결과로 교체하며, 픽셀 아트 확인용 최근접 필터도 선택할 수 있습니다.
- 좌우/상하 확대 비교는 타일마다 동일한 CGImage 프레임을 두 레이어에 공유해 애니메이션·색상·보정 조건을 맞추고, 공통 배율·팬 위치에 보간만 다르게 적용합니다. 비교 칸 크기를 디코딩 요청에도 반영하며 두 번 디코딩하지 않습니다. 고화질 확대를 끄거나 Esc를 누르면 비교를 먼저 종료하고 기존 배율·팬을 보존합니다. 표시 설정은 내보내기 결과를 변경하지 않습니다.
- 이동 방식 5개와 고화질 확대·비교 4개 동작은 ShortcutAction을 통해 메뉴와 키보드가 같은 상태 변경을 사용합니다. 이전 사용자 지정 단축키에 새 기본값만 병합하고, Option 특수 문자/한글 입력은 지원 키의 물리 위치로 폴백합니다.
- 집중 보기의 1:1 모드는 현재 8K 미리보기 상한을 둡니다. 초대형 이미지의 완전한 1:1 이동은 다음 단계의 타일 피라미드 렌더러가 담당합니다.

Quick Look, Image I/O, Core Image는 macOS 동적 프레임워크이므로 앱 번들에 대형 코덱 바이너리를 복제하지 않습니다. 시스템 미지원 형식만 작은 독립 디코더로 추가하는 것이 용량 원칙입니다.

256 GB 내부 SSD를 고려해 앱 자체의 영구 이미지 디스크 캐시를 추가하거나 폴더 원본 9~30 GB를 복제하지 않습니다. 앱의 출력 이미지 캐시는 메모리에만 둡니다. 128 + 64 MiB는 기본 모드의 출력 캐시 합계이며 전체 앱 메모리 상한이 아닙니다. 코덱 임시 공간·GPU·레이어·현재 화면 참조·OS Quick Look 및 파일 캐시는 별도이고, 자동 조절이 다른 앱에 미치는 영향을 완전히 없애는 것은 아닙니다.

알고리즘 비교, 대용량 계산과 검증 범위는 [이미지 로딩 설계와 검증](IMAGE_LOADING.md)을 참고하세요. 그 문서의 M3 정밀 4개 디코더 속도 표는 이전 엔진 개선 기록이며 현재 기본 쾌적 모드의 벤치마크가 아닙니다.

## 입력과 패널

- 썸네일 패널 배치는 ThumbnailPanelPlacement 하나로 관리합니다. 툴바와 메뉴에서는 숨김·왼쪽·오른쪽·아래·위를 중첩 단계 없이 바로 고르며, 위·아래에서는 가로 지연 그리드, 좌·우에서는 세로 지연 그리드를 재사용합니다.
- 팬 방식은 PanInteractionMode로 저장합니다. AppKit 이벤트 감시 영역은 이미지 캔버스에만 붙어 정보 패널이나 설정 창의 스크롤을 가로채지 않습니다.
- 오른쪽 보조 패널은 정보와 편집 중 하나만 열어 좁은 창에서도 이미지 영역을 보존합니다.
- i 정보 패널의 수정 시트는 파일 이름·수정일과 TIFF/EXIF/GPS 표준 태그를 편집합니다. 픽셀 크기·포맷·비트 심도·UTI처럼 파일에서 계산되는 속성은 읽기 전용입니다.
- 지도 버튼은 EXIF GPS가 유효할 때만 보이며, 클릭할 때만 [Apple 지도 링크](https://developer.apple.com/library/archive/featuredarticles/iPhoneURLScheme_Reference/MapLinks/MapLinks.html) 또는 [Google Maps URL](https://developers.google.com/maps/documentation/urls/get-started)을 엽니다. API 키나 위치 업로드는 없습니다.

## 이미지 비교

- `PresentationMode.folderComparison`은 일반 라이브러리와 별개의 화면입니다. `FolderComparisonStore` 안에 두 `FolderComparisonPane`을 두어 목록·폴더 접근 권한·선택·확대·팬을 분리하고, 기존 ImagePipeline·ThumbnailPipeline·자원 조절기를 공유합니다.
- `ComparisonFolderOpenPanel`은 A와 B를 단일 폴더 선택 창으로 차례로 받습니다. 두 단계가 모두 완료된 뒤 비교 목록을 교체하므로 중간 취소는 기존 상태를 유지합니다. 선택 도중 잠금 변경과 재진입도 차단합니다.
- 폴더 교체 시 이전 목록과 선택을 즉시 비우고 취소·세대 검사를 함께 적용합니다. 같은 순번의 이전 이미지나 늦게 완료된 스캔이 새 폴더를 덮지 못합니다. 비교에서 나가면 진행 중 스캔을 취소하고 일반 라이브러리와 선택으로 복귀합니다.
- 공통 이동은 잠금·로딩·빈 칸을 제외한 가장 긴 목록을 기준으로 합니다. 짧은 목록의 끝에서는 `ComparisonEndBehavior`에 따라 마지막 이미지를 유지하거나 반복합니다. 최장 목록은 끝에서 멈추며 동수 목록은 하나라도 이동할 수 있으면 나머지를 유지하고 진행합니다. 개별 이동·번호 점프·썸네일 선택은 독립적이며 파일명 매칭은 하지 않습니다.
- `ComparisonFilmstrip`은 각 칸 하단에서 기존 썸네일 파이프라인으로 보이는 셀만 읽고 현재 이미지 위치를 따라갑니다. 잠긴 칸은 클릭 이동을 막고 스크롤만 허용합니다. 상하 배치에는 더 낮은 썸네일 행을 사용합니다.
- AnyLayout으로 가로/세로 배치를 전환합니다. 아랍어에서도 A는 물리적으로 왼쪽/위, B는 오른쪽/아래를 유지합니다. 각 캔버스가 포인터/스와이프를 처리하지만 창 단축키는 첫 감시자만 받아 중복 실행을 막습니다.
- 연동 선택 시 배율·팬·기본 스케일 모드를 복사하고 진행 중 제스처 변위를 공유합니다. 제스처 종료 후 정밀 재요청하는 기존 타일을 재사용합니다. 화면 배치와 연동 여부만 저장하며 폴더 접근 권한을 재실행 뒤까지 저장하지 않습니다.
- 비교 타일은 보정 없는 원본 표시이며 파일 변경 명령은 막습니다. 숨겨진 일반 라이브러리의 파일이 실수로 편집·내보내기·바탕화면 대상이 되지 않게 AppStore와 메뉴에서 제한합니다.

## 전자 앨범

- `SlideshowSettings`가 기본 5초, 1~300초 정수 범위와 마지막 이미지 반복/정지 규칙을 정의합니다. AppStore는 재생 상태를 저장하지 않고 시간·반복 설정만 저장합니다.
- 타일의 `onPresentationReady`는 첫 미리보기/정밀 프레임 또는 읽기 오류 표시 시 현재 파일을 알립니다. AppStore가 파일 식별자를 확인하고 같은 파일의 후속 정밀 렌더·애니메이션 콜백은 무시합니다. 표시 전 로딩 시간을 재생 시간에 포함하지 않습니다.
- 카운트다운은 취소 가능한 단일 Task와 세대 토큰으로 구현하며 대기 중 AppStore를 강하게 붙잡지 않습니다. 선택·간격 변경 시 기존 시간을 폐기하므로 오래된 타이머가 연속 넘김을 일으키지 않습니다.
- 재생은 한 장·화면 맞춤·집중 모드로 시작합니다. 집중/뷰어 이탈, 앱 비활성, 잠자기, 창 종료, 파일 및 정보 수정 작업은 일시정지합니다. 재생 중에만 [ProcessInfo의 idleDisplaySleepDisabled](https://developer.apple.com/documentation/foundation/processinfo/activityoptions/idledisplaysleepdisabled) 활동 토큰을 보유하고 중지 시 해제합니다.

## 바탕화면 설정

- 시트를 열 때 `WallpaperRequest`가 파일·보정·현재 화면 ID와 연결 화면 목록을 고정합니다. 실제 적용은 사용자의 적용 버튼 뒤에만 실행합니다.
- `WallpaperService`는 기존 ImagePipeline을 이용해 화면 크기에 맞춘 최대 8192px SDR 정적 이미지를 만들고 전용 renderer actor에서 PNG로 저장합니다. 애니메이션은 첫 프레임만 쓰고 EXIF/GPS 등 원본 메타데이터는 복사하지 않습니다.
- PNG는 Application Support의 현재 번들 ID 아래 `Wallpapers/<UUID>.png`로 보존합니다. 일반 이미지의 영구 캐시가 아니라 사용자가 요청한 바탕화면 출력물입니다. 이전 성공 파일은 다른 Spaces의 참조 가능성 때문에 자동 정리하지 않습니다.
- `DesktopWallpaperClient` 프로토콜 뒤의 `WorkspaceWallpaperClient`가 화면 ID를 다시 확인하고 메인 스레드에서 공식 [NSWorkspace.setDesktopImageURL](https://developer.apple.com/documentation/appkit/nsworkspace/setdesktopimageurl(_:for:options:))을 호출합니다. [DesktopImageOptionKey](https://developer.apple.com/documentation/appkit/nsworkspace/desktopimageoptionkey)로 비율 유지, 채우기/맞춤과 검정 여백을 지정합니다. 사라진 화면을 다른 화면으로 임의 대체하지 않습니다.
- 일부 화면에만 적용되면 PNG를 남기고 실패 화면을 알립니다. 모든 화면 적용이 실패한 경우 이번에 만든 UUID PNG만 경로 검증 뒤 지웁니다. 원본과 기존 성공 파일은 삭제하지 않습니다.
- 자동 테스트는 가짜 화면 클라이언트를 주입해 성공·부분 실패·전체 실패와 원본 보존을 검사합니다. 실제 사용자의 바탕화면은 테스트에서 변경하지 않습니다.

## 현지화

- `Localizable.strings`는 한국어 키를 기준으로 8개 언어가 같은 키 집합과 서식 지정자를 갖도록 테스트합니다.
- SwiftUI의 정적 문구는 macOS 번들 현지화를 사용하고, 열거형 제목·오류처럼 실행 중 조합되는 문구는 `L10n`을 통해 같은 리소스를 읽습니다.
- 배포 스크립트는 각 `.lproj`를 앱의 `Contents/Resources`에 복사하므로 Finder 앱 이름의 `InfoPlist.strings`와 앱 화면이 같은 언어를 사용합니다.
- 언어 선택은 별도 사설 설정을 만들지 않고 macOS의 전역 또는 앱별 언어 설정을 따릅니다. 아랍어에서는 시스템의 오른쪽에서 왼쪽 레이아웃 전환을 따르되, 두 폴더 비교의 물리적 A/B 위치는 고정합니다.

## 기본 앱 연결

- `Info.plist`의 문서 타입 선언으로 알맹Re를 폭넓은 이미지 UTI의 Viewer 후보로 등록합니다. QOI와 PCX는 앱이 가져오는 자체 UTI 선언을 사용합니다.
- 사용자에게 보이는 이름과 배포 번들은 `알맹Re`로 통일하되, 번들 ID `org.openimageviewer.ImageViewer`, 실행 파일·Swift 모듈 `ImageViewer`, `ImageViewer.*` 설정 키와 문서 타입은 유지합니다. 이름 변경으로 사용자 설정을 새 도메인에 만들거나 기본 앱 연결을 자동 재설정하지 않습니다.
- 설정 화면의 `DefaultAppAssociationStore`는 JPEG, PNG, RAW 같은 23개 형식군을 보여 주며 사용자가 고른 형식의 UTI만 처리합니다.
- 적용은 macOS 12 이상 공식 `NSWorkspace.setDefaultApplication` API를 사용합니다. 운영체제의 사용자 확인을 우회하지 않으며 선택하지 않은 형식의 연결은 건드리지 않습니다.
- 현재 기본 앱은 각 UTI의 실제 처리 앱 URL과 현재 번들을 비교해 없음·일부·전체 상태로 표시합니다.

## 비파괴 조정

조정값은 파일 URL별 ImageAdjustments에만 저장됩니다. 화면에서는 Core Image 필터 체인으로 적용하고, 사용자가 내보내기를 선택했을 때 같은 체인을 원본 해상도로 평가합니다. 밝기·채도·회전 같은 픽셀 편집은 원본 파일을 덮어쓰지 않습니다.

잘라내기 시트는 회전 후 이미지의 좌상단 기준 정규화 영역을 임시 보관하며, 적용할 때만 열 당시 ImageAsset에 반영합니다. 자유/원본/1:1/4:3/3:4/3:2/2:3/16:9/9:16 비율, 영역 이동·모서리 드래그·수치 입력을 지원합니다. 회전 동작은 자르기 영역도 함께 변환하므로 같은 원본 부분이 남습니다. 화면의 실제 크기는 잘린 원본 치수를 사용합니다. 미리보기 디코딩은 자르기로 줄어든 면적을 보완하되 긴 변 요청의 최대 4배·8192픽셀로 제한합니다.

편집 필터는 노이즈 감소, 노출, 상대 색온도, 색조, 색선명도(Vibrance), 휘도·대비·채도, 하이라이트, 반전, 선명도 순서로 적용합니다. 색온도 양수는 따뜻하게, 음수는 차갑게 조정하며 카메라의 실제 Kelvin 값은 아닙니다. 노이즈 감소와 선명도는 해상도에 영향을 받는 필터이므로 최종 디테일은 실제 크기 보기와 저장 파일로 확인합니다. 무보정은 기존 빠른 표시 경로를 유지하고 슬라이더 연속 조정은 90ms 동안 중간 요청을 취소합니다.

내보내기 기본 이름은 `-edited` 접미사를 사용하며 동일 경로·심볼릭 링크·하드 링크를 통한 원본 덮어쓰기를 거부합니다. 출력 이미지의 방향과 픽셀 치수로 EXIF/TIFF 정보를 갱신합니다. 편집값은 현재 실행 중에 사진별로 유지되고 앱 재실행 시 복원하지 않습니다.

## 메타데이터 편집 안전성

- 정보 수정은 사용자가 i 패널에서 저장을 명시적으로 선택할 때만 실행합니다.
- 확장자 변경, 중복 파일명과 숫자·GPS 범위를 먼저 검증합니다.
- ImageMetadataWriter는 Image I/O의 무손실 복사 경로로 임시 파일을 완성한 뒤 원본 경로를 교체하므로 픽셀을 다시 압축하지 않습니다.
- 지원하지 않는 형식에서는 내장 태그 입력을 잠그고 파일 이름과 파일 시스템 수정일만 허용합니다.
- 저장 후 소스·렌더·Quick Look 캐시를 폐기하고 폴더를 다시 스캔해 변경된 이름과 정보를 즉시 반영합니다.

## 다중 선택과 일괄 파일 작업

- AppStore는 활성 이미지와 URL 집합으로 관리하는 다중 선택을 분리합니다. 일련번호 순서는 클릭 순서가 아닌 현재 목록 순서입니다. 시트를 열 때 대상을 고정하고 작업 중 폴더 전환·다른 파일 작업을 막습니다.
- BatchRenamePlanner는 파일명·번호 범위·대소문자와 Unicode 정규화를 고려한 중복·기존 경로를 검증하고 원본 파일 식별자와 수정 시각을 함께 캡처합니다. 미리보기 계산은 UI 스레드 밖에서 실행됩니다.
- BatchRenamer는 적용 직전 상태를 재검증하고 원본 폴더의 비공개 임시 디렉터리를 거쳐 이름을 바꿉니다. macOS의 배타적 rename으로 기존 파일을 덮어쓰지 않으며 대소문자 변경과 이름 순환 교체를 지원합니다. 실패 시 복구하고 복구가 막히면 남아 있는 파일의 위치를 오류에 표시합니다.
- 성공 후 기존 라이브러리의 URL·선택·활성 이미지·보정값을 함께 치환하며 여러 폴더에서 명시적으로 연 파일 목록도 보존합니다. 렌더·썸네일 캐시를 비우고 정보를 다시 읽습니다.
- BatchImageExporter는 기존 ImageExporter를 한 장씩 호출합니다. 저장 폴더 안의 임시 파일을 완성한 뒤 배타적으로 최종 이름에 옮기며 파일별 실패와 취소 결과를 반환합니다. 계획과 실행 모두 원본 덮어쓰기를 금지합니다. 현재 내보내기 파이프라인과 동일하게 다중 프레임은 첫 프레임만 저장합니다.

## 폴더 트리 탐색

`FolderTreeStore`는 한 단계 디렉터리 목록과 펼침 상태를 소유하고 UI용 평탄 행을 제공합니다. 디렉터리 읽기는 메인 스레드 밖에서 수행하며 숨김·패키지·심볼릭 링크는 제외합니다. root 변경과 재읽기의 이전 결과가 새 트리에 섞이지 않도록 세대별로 적용합니다.

`FolderTreeView`는 현재 폴더를 트리에 드러내고, 폴더 선택을 `AppStore.openFolderFromTree`에 전달합니다. 일반 보기는 `currentFolderURL`을 이미지 유무와 별개로 보관합니다. 트리에서 연 빈 폴더는 정상 탐색 상태로 처리하고, 몽땅보기 모드는 유지합니다. 비교 중에는 선택된 A/B 칸만 바꾸며 기존 잠금 조건을 따릅니다. `showsFolderTree`는 독립적인 표시 설정이고 왼쪽 썸네일과 한 열을 공유합니다.

양축 스크롤의 짧은 목록은 최소 높이를 화면 높이로 지정해 위쪽에 정렬합니다. 기본 스크롤 위치와 선택 폴더로 이동하는 기준점도 위쪽·왼쪽으로 통일합니다.

## 통합 열기

`ImageOpenPanel`은 이미지와 폴더를 함께 고르는 공통 창을 제공합니다. `ImageLibrary.open(urls:)`가 메인 스레드 밖에서 실제 파일 종류를 확인하며, 폴더는 직계 사진 목록, 단일 이미지는 이웃 목록과 선택 위치, 여러 항목은 중복 없는 합친 목록으로 준비합니다. 보안 범위는 읽기와 열린 목록이 사용하는 동안 보관합니다.

`AppStore.open(urls:)`는 일반 보기와 이미지 비교의 활성 칸에 같은 열기 규칙을 적용합니다. 비교 모드와 반대편 칸, 잠금은 유지합니다. 기존 `openFolder` 단축키 식별자는 보존하고 표시 이름은 ‘열기’로 바꿉니다. 네이티브 파일 메뉴에 실제 단축키를 등록하므로 빈 시작 화면에서도 `⌘O`를 사용할 수 있습니다.
